# 只读零写册（08-windowcut）

锁定日期：2026-11-21（当日不得改口）
产品：业务窗关账 · 接口 http://127.0.0.1:11032 · 库 `data/app.db`

## 一、缺陷与复现

- 缺陷：`viewer`（role=`只读`）可成功关窗、物化、入账，正式表被改。
  根因在 `backend/auth.py::require_writer`：只校验登录，未校验角色，只读被当写者放行；
  写接口分散在各 `*_svc`，没有统一的鉴权前置。
- 复现（改前，红）：
  `POST /api/windows/2/close`（viewer）→ 200；`POST /api/windows/1/materialize`（viewer）→ 200。
- 复现测试：`tests/test_readonly_zero_write.py`，改前 3 条全红。

## 二、口径（二选一，已选甲，不得混用）

- **甲路径（选定）**：role 为「只读」时，所有写入口在鉴权前置处**整笔拒绝**，
  正式业务表零改，仅落一条 `write_denied` 拒权审计。
- 乙路径（审批后服务端代写）：**本仓不采用**。
  不实现 `write_request`/审批队列，也不存在「拒绝 + 代写」并存的混合路径。
- 朝向乙的任何改动（只读可提交 write_request、服务端代写）视为偏离本册，须拒写并记「权限偏了」。

## 三、实现落点

| 层 | 文件 | 落点 |
|----|------|------|
| 鉴权前置 | `backend/auth.py` | `authorize_write(conn, authorization, attempt, target, lock_key)`：写角色放行，只读整笔 403 + `write_denied`；`role_of` 从 `users` 取角色；`write_gated` 给写路由打标；`/api/write-policy` 暴露口径 |
| 窗口写 | `backend/windows_svc.py` | `create_window` / `close_window` 先过 `authorize_write`，再取窗锁 |
| 物化写 | `backend/materialize_svc.py` | `materialize` / `partition_stub` 过闸 |
| 其余写 | `ingest_svc` / `hold_svc` / `late_svc` / `reopen_svc` / `locks` | 全部写路由过闸并打标 |
| 拒权可见 | `backend/audit_svc.py` | `GET /api/audit/denials` 单列 `write_denied` |

写角色集合：`管理员`、`关账员`。只读角色：`只读`。
只读分支允许写的表仅两处旁证：`contention_log`（争用）与 `audit_trail`（拒权审计）。

## 四、五处同态（须一致）

同一窗、同一请求下，五处必须同态：

1. **角色**：`users.role` = 只读，账号与角色表不再撕裂。
2. **拒权审计**：`audit_trail.action='write_denied'`，payload 含 `attempt/role/policy/locked_on`。
3. **窗口状态**：`windows.status` 未被只读改动。
4. **物化**：`materializations` 零新增（只读）。
5. **争用**：只读后到与管理抢写同窗 → `contention_log` 记一条（actor=viewer），后到只记争用。

## 五、并发抢写同窗

- 管理先占窗锁（`window_locks`，如 `window:2`）；只读后到同窗写：
  鉴权前置先拒（403，`write_denied`），并因锁被他人持有记一条争用；业务表零改。
- 持锁管理在其事务结束后释放锁，可继续完成关窗/物化。
- 后到写者「只记争用」，不得获取写权，不得改窗口状态/物化。

## 七、禁止

- 禁止只改前端按钮隐藏/置灰冒充修复（按钮隐藏不过关）。
- 禁止只读分支改任何业务表。
- 禁止甲乙路径混用：只读要么整笔拒绝，要么（本仓不采用）审批后服务端代写，二者不得并存。
